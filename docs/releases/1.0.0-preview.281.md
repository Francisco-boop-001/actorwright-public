# Actorwright 1.0.0-preview.281

**Windows authoring workflows require a workspace on K:. Set ACTORWRIGHT_PROTECTED_ROOT to your own game installation before use; the private default does not protect a differently located game.** A virtual K: mapping is not a verified installation route yet.

The release-attached verification receipt is the authority for the exact source

## Workspace setup

Authoring requires an ordinary writable workspace on `K:`. Set the protected
root to the actual local game installation; this configures a read-only safety
boundary and does not authorize deployment into the game directory. The paths
below are examples and must be replaced for the local machine:

```powershell
$env:ACTORWRIGHT_WORKSPACE_ROOT = 'K:\ActorwrightWorkspace'
$env:ACTORWRIGHT_PROTECTED_ROOT = 'D:\Games\Skyrim Special Edition'
$env:DOTNET_BUNDLE_EXTRACT_BASE_DIR = 'K:\ActorwrightWorkspace\.bundle'
```

The private default protected root does not protect a differently located
installation. `K:` must be a supported local workspace. The receipt identifies
the applicable NTFS and clean-clone checks and their results; this setup note
does not attest that they passed.

## Build and command examples

The repository pins .NET SDK 10.0.301. From its root, the documented canonical
build command is:

```powershell
.\tools\build\build.ps1
```

Set `$Actorwright` to the exact CLI executable being evaluated, then inspect its
identity and command surface:

```powershell
$Actorwright = 'C:\Path\To\the\verified\cli\actorwright.exe'
& $Actorwright version --protocol 2 --json
& $Actorwright capabilities --json
```

These are usage examples. The release receipt identifies the exact binaries and
their build, test, package, and compatibility results.

## External rendering tools and test input

Renderer-dependent workflows use user-installed Blender 4.5.1, PyNifly 27.4.0,
and Texconv 2026.5.7. They are not bundled; obtain them from their official
providers and review their licenses. Exact profile admission and renderer
execution must be reported separately. See
`docs/external-rendering-prerequisites.md` and `docs/third-party-licenses.md`.

The positive Skyrim Finish integration checks require a user-supplied local
`Skyrim.esm` through `ACTORWRIGHT_TEST_SKYRIM_MASTER`, for example:

```powershell
$env:ACTORWRIGHT_TEST_SKYRIM_MASTER = 'D:\Games\Skyrim Special Edition\Data\Skyrim.esm'
```

Use the actual ordinary local path. The test reads the master without changing
it and extracts only the validated canonical PACK record into an owned
synthetic fixture. The full master is not distributed; this variable is a test
prerequisite, not a normal application setting. Missing or invalid input is a
refusal, not a passing positive test.

## Appearance assets

The public distribution omits the private default appearance provider and game-derived example meshes. NPC creation requires a licensed workspace provider and its hash-bound manifest, template, mesh, texture, and dependency files. The desktop checks the selected provider before enabling creation and checks it again at build time. Synthetic meshes included for verification are not game-ready assets.

## Verification and limits

Required clean-source, packaged, NTFS, and remote-CI gate outcomes are recorded
in the release-attached verification receipt. Focused checks do not substitute
for those identity-bound results.

Static artifact validation and off-engine rendering do not prove in-game behavior, appearance, save compatibility, or human visual acceptance. Protocol 2 does not reuse the legacy K-local root-admission diagnostic; the static review found no concrete protected-root write bypass. Whole-file buffering and failure-evidence coverage gaps also remain documented limitations.

The optional runtime-script build inspector still depends on a private patched Caprica distribution that is not provisioned by this release. An unmodified upstream Caprica download does not satisfy those pinned prerequisites. This limitation is separate from the main application build and packaging of the supplied precompiled scripts.
